# 写给人看的中文

## 判断标准

一段文字像不像人写的，取决于一件事：**说话的人有没有具体的事要说。**

有具体问题的人会直接给结论、跳过读者已经知道的东西、在没把握的地方停下来。AI 的默认姿态是对"平均读者"解释一切，于是出现铺垫、报幕、面面俱到的评价。

去 AI 腔不是换词，是把文字还原成"一个人在为某个具体问题说话"。判断依据是：删掉一句之后，读者是否少知道了什么。少了，留着；没少，删。

## 五步改写

1. **先问这段文字在回答什么问题。** 答不出来，说明它在空转，删掉重写。
2. **删掉关于文字本身的句子。** "本文""这篇""下面我们将""先给结论""分三点讲"——这些句子不携带信息。
3. **替换模板句式。** "不是 A 而是 B"、"不仅……更是……"、"先 X 后 Y"（顺序无意义时）、机械的三段排比。
4. **收敛评价与虚词。** "非常重要""关键""值得注意""建议记住""最容易被忽视"；"此外""同时""值得注意的是""综上所述"。
5. **复读，再删一个形容词。** 多数时候删掉后意思不变，语气反而更硬。

## 四类中文教程腔

这四类是把英语写作检查清单搬过来最容易漏掉的，它们不靠词表也能识别：

| 类型 | 长什么样 | 改成 |
|---|---|---|
| **元话语** | "这篇文章会讲清判断标准" | 直接给标准 |
| **结构宣告** | "两条核心结论先给""下面分三点" | 直接说第一条 |
| **评价性包装** | "建议背熟""最容易被追问""非常关键" | 说明后果："面试官通常会追问这一点" |
| **坑叙事** | "踩过的坑""避坑指南""血泪教训" | 写成规则："属性值要加引号" |

## 通用模式

完整词表与中文特有的翻译腔、名词化、被动堆叠，见 `references/ai-patterns.md`。高频的几类：

- **夸大意义**："标志着""为……奠定了基础""在当今快速发展的……时代"
- **模糊归因**："业内普遍认为""有观点指出"——要么给出来源，要么删掉
- **空转抽象**："赋能""闭环""抓手""多维度""深度绑定"
- **翻译腔**："对代码进行了优化""基于……的基础上""对于这个问题，我们需要考虑的是"
- **连接词堆积**：每段开头一个"此外/同时/值得注意的是"

## 改写示例

**示例 1（元话语 + 结构宣告）**
> 这篇用我真实做过的场景讲清楚判断标准。两条核心结论先给：一是 useMemo 和 useCallback 不是"性能开关"，是"引用稳定性工具"。

改成：

> useMemo 和 useCallback 优化的是引用稳定性。判断依据是：计算贵不贵、引用会不会被比较。

**示例 2（对仗模板）**
> 清理函数不是"卸载时执行"，而是"下次执行前 + 卸载时"。

改成：

> 清理函数在两个时机执行：下次 effect 之前，以及组件卸载时。

**示例 3（坑叙事）**
> 两个已知的坑（踩过了，别重踩）：SVG 属性不加引号会报错。

改成：

> 写 SVG 时属性值要加引号：`font-family="{FONT}"`。

**示例 4（宣传腔）**
> 在当今 AI 快速发展的时代，掌握提示词工程对每一位开发者都至关重要。

改成：

> 提示词写不好，同一个模型的表现会差一个档。

**示例 5（翻译腔 + 名词化）**
> 我们对接口层进行了重构，并且对于错误处理进行了统一。

改成：

> 我们重构了接口层，错误处理也统一到一处。

## 检查清单

交付前逐条过：

- [ ] 开头第一句是内容，不是"本文/这篇/下面"
- [ ] 没有宣告结构（"先给结论""分三点"）
- [ ] 没有替读者判断重要性（"重要""关键""建议记住"）
- [ ] "不是 A 而是 B"只用在纠正真实误解处
- [ ] 三件套排比不超过一处，且三项确实同等重要
- [ ] 每个"此外/同时/值得注意的是"都能直接删掉
- [ ] 没有无法追溯的"业内/普遍/有观点认为"
- [ ] 没有"进行了/对……进行"这类名词化
- [ ] 技术术语保持原样，没有为了口语化改错
- [ ] 通读一遍，节奏有长有短，不是每句一个长度

## 边界

去 AI 腔不是把所有文字改成聊天。以下内容要保留：

- **术语与精确表述**："幂等""事务隔离级别""游标分页"不能换成大白话
- **必要的结构**：长文档需要章节和小标题，但小节开头要直接进入内容，不写"本节将讨论"
- **必要的限定**："通常""在大多数情况下"如果确实成立，保留；不要为了语气硬而删掉准确性
- **个人判断**：真有观点就直接说"我认为"，这比中立叙述更像人

不要做的：为了"人味"加口头垃圾（"说实话""其实吧""懂得都懂"），或者在不该口语的场合用网络流行语。

## 输出格式

改写时给两部分：

1. **改写后的全文**（直接可用，不加解释性标注）
2. **一句话说明改了什么类型的问题**（例如："去掉了开头的元话语和三处评价性包装"）

不要把改动逐句列成对照表，除非用户明确要求看 diff。
